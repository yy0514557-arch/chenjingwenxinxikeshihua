## 使用说明与分析边界

- 本目录的16项是课件在“常用信息图形种类”部分列出的类型标题，不代表它们构成互斥、同一维度的严格分类学。
- 各类型可能从不同维度命名：有的强调数据组织逻辑（如时间轴、层级、地理），有的强调信息任务（如比较、流程、示意），有的强调视觉载体或表现形式（如图片式、手稿、三维）。
- 类型条目中的“工作性定义”“适用情境”“设计检查”和边界说明，是为知识库建立的分析框架，不应误认为PDF逐字给出的定义。
- 已有案例观察仅在PDF图像和文字可支持的范围内陈述；看不清的数值、来源、统计口径或设计意图均标注待核实。
- 后续收到新案例时，优先补充到对应类型文档，并记录原始来源、页码、直接观察、推断和待核实信息。

## 跨类型设计原则

1. **结构先行**：先收集与清洗数据、搭建信息结构，再进行视觉编码和版式排布。
2. **形式匹配内容与读者**：图形形式应匹配信息特点、叙事任务和读者背景。
3. **简化形式，不简化事实**：通过层级、导航和分组降低认知负担，而不是删去必要信息。
4. **视觉元素各司其职**：图表负责数据表达，图标负责识别或编码，插画与照片提供语境，文字负责解释。
5. **审查视觉冗余**：警惕装饰遮蔽数据、制造错误比较或抢占注意力。
6. **建立分层阅读**：提供主题概要、主要信息和深入细节的阅读路径。
7. **进行读者测试**：检验读者能否识别主题、参数、变化、数据与评论的区别。

两者不是一一对应关系：同一种信息图形类型可以组合多种数据逻辑；同一种数据逻辑也可以通过多种视觉类型表达。
