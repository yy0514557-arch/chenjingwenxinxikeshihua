# ISOTYPE｜概念、历史与基础图形设计方法

> **独立专项：03-ISOTYPE信息图。** 不属于“编年／层级／编目／字母表／地理”五种基础信息组织逻辑，也不属于 02 的 17 种市场化表现形式。专项研究图符语言、信息转译、视觉编码、历史文献、案例和设计实践。

## 一、概念与历史边界

**ISOTYPE** 全称 **International System of Typographic Picture Education**（国际图像文字教育系统）。它由 Otto Neurath 及其团队在 1920 年代发展的 **Vienna Method of Pictorial Statistics（维也纳图像统计法）** 演变而来，并于 1930 年代中期以 ISOTYPE 之名推广。Marie Reidemeister（后为 Marie Neurath）承担核心的资料—图像转译（Transformer）工作；Gerd Arntz 发展了具有高度统一性的图符语言。

ISOTYPE 的关键不只是“画风相同的扁平图标”，而是**借助标准化、可重复、可组合的图符，把复杂知识和统计信息转译为大众容易理解的视觉表达**。它是一种有视觉语法和工作方法的信息设计体系。

## 二、分类方式：与既有仓库共存

- **01 基础逻辑（必选且唯一）：** 按作品主要信息关系选择编年、层级、编目、字母表或地理之一。
- **02 表现形式（可多选）：** 仍选已有 01–17 的适用标签，如比较型、流程图型、地标型、文字型／列表型、单一图表型等。
- **03 ISOTYPE 专项（独立）：** 研究与记录视觉语言、统计图符及信息转译方法，供相关项目跨类型调用。
- **04 统计图形（如适用）：** 分别考察作品是否使用象形符号图（pictograph）、比例图、地图或其他统计图。**ISOTYPE 不等同于某一种统计图形。**
- **06 主题设计工作流：** 可在视觉编码阶段调用 ISOTYPE 方法，但不取代前期的基础数据与叙事框架。

**最关键的边界：** ISOTYPE 是“怎样把信息设计成图像”的方法，不是“信息按照什么关系组织”的基础类型，也不是“这张图叫什么产品形式”的市场标签。

## 三、核心方法原则

1. **统一的图形词汇（pictogram vocabulary）：** 面向稳定语义设计简化、易辨、可组合的图符。图符需要在同一作品或系列里保持轮廓、比例、笔画、视角与抽象层级一致。
2. **重复的标准单位：** 当使用数量符号编码时，原则上通过**重复同尺寸图符的数量**表示更多数量，而非通过放大单个图符来暗示数量增长。说明“一个图符代表多少个单位”；必要的半图符、舍入和不完整数量必须制定公开规则。
3. **去透视与高辨识度：** 常用平面化、典型化、轮廓清晰的符号，减少透视与不相关细节。图符先为准确、清楚的概念辨识服务，再追求装饰性。
4. **稳定的图形语法：** 大小、方向、基线、行列间距、排列顺序、色彩、组合和图例形成可持续复用的规则，而不是每项随意改变。
5. **信息转译（transformation）：** 从原始统计和文字资料中筛选事实、明确受众和目的、确定最少但足够的图形信息，再由设计者制定可检验的视觉映射；不是直接把数字换成图标。
6. **文字协同：** 标题、单位、来源、少量说明文字仍承担必要的上下文解释；图符不是对所有语言说明的无条件替代。

### 必须区分的两种使用方式

- **方法级使用（ISOTYPE method）：** 源数据、图符所指、重复单位或结构化语法可验证；实际执行了从信息到规范化图像表达的设计转换。
- **视觉借鉴（ISOTYPE-inspired）：** 只是借鉴 Gerd Arntz 式的扁平、剪影、强对比图形语言，但没有采用可验证的编码语法或信息转译规则。可标“视觉借鉴”，**不能冒称规范 ISOTYPE 统计图**。

**ISOTYPE ≠ ISO 标准化公共标志。** 其名称源自国际图像文字教育系统，不能仅因某些图标用于公共导视或符合 ISO 标准就自动归入 ISOTYPE。

## 四、数据结构与视觉编码（方法示意，不是已有案例数据）

| 基础字段 | 数据含义 | ISOTYPE 编码决策 |
|---|---|---|
| `item_id` | 记录标识 | 稳定追踪与来源关联 |
| `category_id` | 对象或类别 | 确定图符身份或对照分组 |
| `value` | 原始数量（适用时） | 除以 `symbol_unit` 计算应显示的图符个数 |
| `unit` | 数量的计量单位 | 体现在图例与文字说明中 |
| `period` | 统计时期（适用时） | 同一口径比较或按序列组织 |
| `source_id` | 来源标识 | 支撑复核与数据口径说明 |

**一行一个最小记录单元、一列一个原子字段、一个单元格一个值。** 如有多重类别、时间、地理或来源关联，使用规范化表或关联表，而不是单元格多值。图符本体与源数据分离，以图符 ID / 资源文件引用；一个图符的语义、形态与数量单位要有单独字典。

**量化表达示意：** `n_symbols = value / symbol_unit`（此式仅在一图符代表固定数量时成立）。视觉化前必须判断是否可精确整除、是否允许部分图符、是否需要舍入、是否导致图符过密；不能为了画面好看暗改单位比例。没有数值字段的主题型符号系统，允许借鉴图形词汇和组织方法，但不可宣称“重复图符表达数据数量”。

## 五、视觉设计审查清单

| 检查点 | 核查问题 |
|---|---|
| 信息转译 | 是否明确原始资料→筛选原则→图像语义的转化关系？ |
| 图符系统 | 同类符号是否统一、可辨认、可重复并具备语义字典？ |
| 定量映射 | 是否有明确的单位、计数规则、图例和取整说明？ |
| 空间与排版 | 基线、分组、列宽、行距、图符间距能否清楚支持阅读？ |
| 色彩策略 | 色彩是否用于类别/强调，是否与数量映射混淆？ |
| 表现适配 | 设计是否服从作品自身的五大基础逻辑，而非强行套模板？ |
| 证据边界 | 是原始 ISOTYPE 作品、现代方法应用还是视觉风格借鉴？ |
| 来源与版权 | 原作图像和图符资源是否有可靠出处及明确再使用权限？ |

## 六、可以复用的设计制作流程

**确定主题问题与受众 → 审查来源和基础数据结构 → 提炼概念与核心关系 → 设计图符词汇表 → 选择统一的比例、排布与视觉语法 → 建立字段到视觉变量的编码表 → 设计图例、文字与版式 → 校验事实、数量、误读风险 → 记录制作版本。**

本流程是针对仓库的**可复用重建方法**，不声称即为所有历史 ISOTYPE 项目的实际制作步骤。
